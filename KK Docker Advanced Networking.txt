Docker Swarm overlay networks

Create an overlay network
docker network create --driver overlay --subnet 10.0.9.0/24 my-overlay-network

overlay driver → allows containers on different swarm nodes to communicate securely.

subnet → defines the internal IP range for that network.

my-overlay-network → the name of the network.

This network spans all nodes in the swarm.


Deploy a service using that network

docker service create --replicas 2 --network my-overlay-network nginx

--replicas 2 → runs two containers (tasks) of the Nginx service.

--network my-overlay-network → attaches those containers to the overlay network.

nginx → the image used.

Now both Nginx containers can communicate across nodes through the overlay network.



Ingress network

It demonstrates how a user’s HTTP request (e.g., http://192.168.1.5:80) reaches a Docker Swarm service that exposes port 80 externally and maps it to port 5000 inside containers.


A built‑in overlay network used by Swarm for external access to services.

It automatically handles load balancing between replicas.

When you publish a port (e.g., -p 80:5000), Swarm creates an ingress routing mesh.

Load balancer
Distributes incoming requests on port 80 to the service’s containers (tasks).

Each container listens on port 5000 internally.

The load balancer ensures traffic is evenly spread across replicas.


Service creation command

docker service create \
  --replicas=2 \
  -p 80:5000 \
  my-web-server

This creates a service named my-web-server with two replicas, each running a container that listens on port 5000.

Routing mesh
Any node in the swarm can receive traffic on port 80.

Swarm routes the request internally to one of the containers, even if it’s on another node.

This is why you can access the service from any node’s IP.
