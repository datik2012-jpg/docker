/////////////////Docker Registry ////////////////


Run your own local Docker registry

Local Host:

Image name → my-image

Description → your built image

Registry:

Image → registry:2

Port → 5000

docker run -d -p 5000:5000 --name registry registry:2
docker image tag my-image localhost:5000/my-image


Explanation
The first command starts a local Docker registry container named registry on port 5000.

The second command tags your image so it can be pushed to that registry (localhost:5000/my-image).

After this, you can push your image with:

docker push localhost:5000/my-image


docker push localhost:5000/my-image
docker pull localhost:5000/my-image
docker pull 192.168.56.100:5000/my-image

docker push localhost:5000/my-image → uploads your image to the local registry running on port 5000.

docker pull localhost:5000/my-image → downloads the same image back from that local registry.

docker pull 192.168.56.100:5000/my-image → pulls the image from a registry hosted on another machine (IP 192.168.56.100) on port 5000.

Let's practice deploying a registry server on our own.
Run a registry server with name equals to my-registry using registry:2 image with host port set to 5000, and restart policy set to always.

Note: Registry server is exposed on port 5000 in the image.


Here we are hosting our own registry using the open source Docker Registry.

NOTE: You do not need to run docker login for this local registry setup because authentication is not configured. This registry allows for anonymous access.

///////////////////////Docker Orcestration - Docker Swarm ///////////



Initialize the Swarm:
docker swarm init

Add worker nodes:
docker swarm join --token <worker-token> <manager-ip>:2377

Add manager nodes (optional)
docker swarm join --token <manager-token> <manager-ip>:2377

Verify the cluster
docker node ls

Deploy a service

docker service create --name web --replicas 3 -p 80:80 nginx


Check services
docker service ls

Inspect tasks (containers)
>docker service ps web
Shows where each replica is running.

Scale a service

docker service scale web=5

Remove a service
docker service rm web

Leave the Swarm
On a worker:
docker swarm leave
On a manager (to remove the cluster):
docker swarm leave --force


Summary Table
Action	Command
Initialize Swarm	docker swarm init
Join worker	docker swarm join --token <worker-token> <manager-ip>:2377
List nodes	docker node ls
Create service	docker service create --name web --replicas 3 -p 80:80 nginx
Scale service	docker service scale web=5
Remove service	docker service rm web
Leave Swarm	docker swarm leave --force


Docker Swarm stack using a docker‑compose.yml
version: "3.9"

services:
  web:
    image: nginx:latest
    ports:
      - "80:80"
    deploy:
      replicas: 3
      restart_policy:
        condition: on-failure

  redis:
    image: redis:alpine
    deploy:
      replicas: 1

Note: Swarm requires Compose version 3+ because it includes the deploy: section.


Initialize Swarm (if not already)

docker swarm init


Deploy the stack
Use docker stack deploy instead of docker compose up.
docker stack deploy -c docker-compose.yml mystack

-c → compose file

mystack → stack name (prefix for all services)

Swarm will:

schedule containers across nodes

create overlay networks

ensure desired replicas

load‑balance traffic

Check the stack status:
docker stack ls

List services in the stack:
docker stack services mystack

See where tasks (containers) are running:

docker stack ps mystack

Update the stack:
Just edit your docker-compose.yml and redeploy:
docker stack deploy -c docker-compose.yml mystack

Swarm performs:

rolling updates

zero‑downtime deployments

rollback on failure

Remove the stack:
docker stack rm mystack

This removes:

services

tasks

networks created by the stack
