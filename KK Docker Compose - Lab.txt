# 🐳 Local Docker Swarm: Manager + Worker Nodes  
A complete guide for running a multi‑node Docker Swarm cluster locally on one machine using Docker‑in‑Docker (DinD).

---

## 📌 Overview  
This setup simulates a real Swarm cluster:

- 1 Manager node  
- Multiple Worker nodes  
- All running locally using Docker containers  
- No VMs required  
- Perfect for learning, testing, and development  

---

## 🚀 Step 1 — Initialize the Swarm (Manager Node)

Create the Swarm manager on your host machine:

```bash
docker swarm init
This outputs a join command similar to:

Code
docker swarm join --token SWMTKN-1-xxxx manager-ip:2377
Save this token — workers will use it.

🛠️ Step 2 — Create Worker Nodes (Docker‑in‑Docker)
Run Docker‑in‑Docker containers to simulate worker machines:

bash
docker run -d --privileged --name worker1 docker:dind
docker run -d --privileged --name worker2 docker:dind
Each container is now a separate Docker engine.

🔗 Step 3 — Join Workers to the Swarm
Enter worker1:
bash
docker exec -it worker1 sh
Inside worker1, run:

bash
docker swarm join --token <token> <manager-ip>:2377
Repeat for worker2:
bash
docker exec -it worker2 sh
docker swarm join --token <token> <manager-ip>:2377
📋 Step 4 — Verify the Cluster
Back on the manager node (your host):

bash
docker node ls
Expected output:

Code
ID        HOSTNAME   STATUS   AVAILABILITY   MANAGER STATUS
xxxx      manager    Ready    Active         Leader
xxxx      worker1    Ready    Active
xxxx      worker2    Ready    Active
You now have a functioning multi‑node Swarm cluster.

📦 Step 5 — Deploy a Stack (Optional)
Create a stack.yml:

yaml
version: "3.9"

services:
  web:
    image: nginx
    ports:
      - "8080:80"
    deploy:
      replicas: 3
      placement:
        constraints:
          - node.role == worker
Deploy it:

bash
docker stack deploy -c stack.yml mystack
Check services:

bash
docker service ls
🧹 Step 6 — Clean Up
Remove the stack:

bash
docker stack rm mystack
Leave the swarm:

bash
docker swarm leave --force
Stop worker nodes:

bash
docker rm -f worker1 worker2
📝 Notes & Best Practices
Use Docker‑in‑Docker for local clusters — fast and lightweight

Workers must run in --privileged mode

Use docker exec to access worker nodes

Use docker node ls to monitor cluster health

Use placement constraints to control where services run
