//////////////Docker Service Swarm -In Depth ////////////
Docker service is the Docker Swarm command used to manage services in a Swarm cluster — things like creating, listing, scaling, updating, and removing services. It only works when Docker is running in Swarm mode and must be executed on a manager node.
docker service is a cluster‑level management command in Docker Swarm.
A service   in Swarm is a declarative description of how containers should run across multiple nodes — including the image, number of replicas, ports, constraints, and restart behavior. 


docker service create — Create a new service (e.g., run Nginx across nodes) 

docker service ls — List all services in the swarm 

docker service ps — Show tasks (containers) for a service

docker service inspect — Detailed info about a service

docker service logs — Fetch logs from service tasks

docker service update — Change service configuration

docker service scale — Increase/decrease replicas

docker service rm — Remove a service

docker service rollback — Undo a bad update

Create a service called simple-web-app with image kodekloud/webapp-color, 3 replicas. The service should be published on port 8083 and make use of environment variable APP_COLOR=pink


the webapp runs on container port 8080

docker service create \
  --name simple-web-app \
  --replicas 3 \
  --publish 8083:8080 \
  --env APP_COLOR=pink \
  kodekloud/webapp-color

Note:

When you create a Docker Swarm service with 3 replicas, it means:

One service definition → Swarm runs 3 container instances (tasks) from it.

Swarm will start 3 containers (called tasks) across your swarm nodes.

If you have 3 nodes, Swarm usually puts 1 container on each node

If you have 1 node, all 3 containers run on that one node

If you have 2 nodes, Swarm spreads them as evenly as possible
