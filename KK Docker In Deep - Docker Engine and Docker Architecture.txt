///////////////////Docker Storage /////////////

When docker installed it creates /var/lib/docker with multiple folders inside

Create volume in that path where volumes: docker volume create data_volume
Will be created: /var/lib/docker/volumes/data_volume
So when we run next time a docker we can mount this volume /var/lib/docker/volumes/data_volume to the docker /var/lib/xxxx :
docker run -v /var/lib/docker/volumes/data_volume:/var/lib/mmysql  alpine:v1  - use the path when path is not part of docker installation (another location which is not par of /var/lib/docker/....  this is BIND mounting)
or will do the same docker run -v data_volume:/var/lib/mmysql  alpine:v1  - command is named VOLUME MOUNTING

So now all the data in case destoryed container  will be left in the volume: /var/lib/docker/volumes/data_volume

Note:if volume not exist before /var/lib/docker/volumes/data_volume and we run docker run -v data_volume:/var/lib/mmysql  alpine:v1 it will be created automatically

Another BIND mounting way:

docker run \
  --mount type=bind,source=/data/mysql,target=/var/lib/mysql mysql

Docker uses storage drivers to manage how container layers and images are stored on disk.
Different drivers have different performance, compatibility, and reliability characteristics — so choosing the right one matters

Driver	Platform	Key Traits	Best Use Case
overlay2	Linux	Modern, fast, stable; uses Linux OverlayFS	Default for most modern Linux distros
aufs	Linux	Older union filesystem; good compatibility	Legacy systems (Ubuntu < 18.04)
btrfs	Linux	Snapshotting, subvolumes, checksums	Advanced setups needing snapshots
zfs	Linux	High reliability, compression, snapshots	Enterprise or data‑intensive workloads
devicemapper	Linux	Block‑level storage; slower, complex	Legacy RHEL/CentOS setups
vfs	Cross‑platform	Simple copy‑on‑write; no layering	Debugging or non‑production use
windowsfilter	Windows	NTFS‑based layering	Default on Windows containers

Docker data directory:
Each folder represents a different subsystem that Docker uses to manage containers, images, networks, and volumes.

Folder	Purpose	Description
aufs	Storage driver data	Contains layered filesystem data when Docker uses the AUFS driver. Each container’s writable layer and image layers live here.
builder	Build cache	Stores intermediate build stages and cache metadata used by docker build.
containers	Container runtime data	Holds metadata and logs for each container (config.json, hostname, mounts, etc.).
image	Image metadata	Contains image manifests, layer references, and version info for all pulled or built images.
network	Networking configuration	Stores bridge, overlay, and other network definitions created by Docker.
plugins	Plugin data	Keeps installed Docker plugins (volume, network, authorization) and their configuration.
swarm	Swarm cluster state	Contains Swarm manager data — cluster configs, certificates, and Raft logs.
tmp	Temporary files	Used for transient data during builds or container operations.
trust	Content trust	Stores Notary signatures and keys for Docker Content Trust (image signing).
volumes	Persistent volumes	Holds data for named volumes mounted into containers. Each volume has its own subfolder.

Docker file with simple FLUSK app:

FROM ubuntu:17.04

RUN apt-get update && apt-get install -y python python-pip

RUN pip install flask

COPY app.py /opt/

ENTRYPOINT FLASK_APP=/opt/app.py flask run --host=0.0.0.0

Run:docker build . to create an image 


Directive	Purpose
FROM ubuntu:17.04	Sets the base image — Ubuntu 17.04.
RUN apt-get update && apt-get install -y python python-pip	Updates package lists and installs Python 2 and pip.
RUN pip install flask	Installs the Flask web framework.
COPY app.py /opt/	Copies your application file into the container’s /opt directory.
ENTRYPOINT FLASK_APP=/opt/app.py flask run --host=0.0.0.0	Defines the command that runs when the container starts — launches the Flask app accessible from any network interface.

or:

ENTRYPOINT FLASK_APP=/opt/app.py FLASK_RUN_PORT=8080 FLASK_ENV=development flask run --host=0.0.0.0

or:

ENV FLASK_APP=/opt/app.py
ENV FLASK_RUN_HOST=0.0.0.0
ENV FLASK_RUN_PORT=8080

ENTRYPOINT ["flask", "run"]

represents a layer in Docker’s AUFS storage driver.

Every image and container is built from multiple layers.

AUFS stores each layer as a directory named by its SHA256 hash.

Inside each layer folder are the filesystem changes (added/modified files).

So those hashes correspond to specific image or container layers.
